# Excalidraw Data

## Text Elements
Indexing: what rag sync does with each changed note ^e001

Git supplies the list of changed notes and their contents. Everything else runs on your computer. ^e002

ADDED OR MODIFIED NOTES ^e003

M  rotate-aws-keys.md
A  eks-upgrade.md ^e005

1. Read
the file from the
origin/main commit,
not your working tree ^e007

2. Chunk
split it into passages
(see the chunking
diagram) ^e009

3. Embed
turn each passage into
768 numbers with a
local model ^e011

4. Save
replace the note's old
passages with the new
ones, or just add them
if the note is new ^e013

DELETED NOTES ^e018

D  old-vpn-setup.md ^e020

Delete its passages
from the index ^e022

A note that cannot be indexed is skipped and reported,
and its old passages are removed. This happens when it is
empty, over 2 MB, not valid text, or too long for the model. ^e025

Last: save the commit ID in .rag/. If a sync stops before this point there is no saved ID,
so the next sync rebuilds every note. ^e028
